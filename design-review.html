Product & Design Review P7 / S1 · CfE
Brain Blast — a maths & literacy practice app for 11–12s

The bones are strong.
The spine is missing.

A full read of the app as built — and where a modern rebuild should spend its effort.

Engine & tests: strong Content depth: uneven Progression: absent 140 tests passing

Brain Blast is already well past hobby-grade. The layered architecture is clean, the spaced-repetition model is properly built, answer-checking is careful, and the test discipline is real. That's the good news, and it's worth saying plainly before the criticism: most of what follows is about a smaller number of high-leverage gaps, not a teardown.

Three of those gaps matter more than the rest. Difficulty never actually progresses — a child who has mastered fractions is served the same fractions forever. Half the content is deep and half is a short fixed list that a child exhausts in a round or two. And a handful of defaults quietly push speed and pressure onto exactly the children who struggle most. Fix those three and the app graduates from a good practice tool to something a child grows through.

B

The missing spine — progression

Ask a child using Brain Blast today “what level are you on?” and there's no honest answer. The only thing that visibly grows is coins and a garden. Competence itself has no shape.

The parts to build a real progression already exist in the codebase, unused. Every topic carries a level band. Mastery is tracked per topic on a rolling window. Spaced repetition decides timing beautifully. What's absent is the piece that turns those into a felt climb: difficulty that moves with the child.

Today · difficulty is flat
Rolling mastery → picks which topic → same difficulty, forever

Mastering a topic changes nothing about the questions it serves. “Secure” is a dead end.

Proposed · difficulty tracks the child
Placement → tier → mastery moves the tier → Secure unlocks Stretch

The same topic gets harder as the child gets better — and eases back after slips.

C

Findings in detail

Each dimension as it stands, where it fails, and the direction to take it. Specifics are drawn from the shipping code.

Interface & motion

Mixed
Now

Single-column card stack, one confident indigo accent, Nunito rounded type, token-driven light/dark, motion kept restrained and reduced-motion honoured. Answer feedback is a highlight — effort praise, a worked explanation every time.

Where it breaks

TimesTable.jsx is built from hardcoded hex and inline styles — white cards on a dark ground when dark mode is on. And Quiz.jsx has a dead ternary where the numeric keypad should be: maths answers are typed on a QWERTY keyboard on mobile.

Direction

Port Times Tables onto the token system so it themes with everything else. Set inputMode="numeric" for maths. Add one small, reduced-motion-safe correct-answer celebration — the reward moment is currently thin.

Navigation & information architecture

Mixed
Now

Flat and clear: hub → subject → topic picker with a prominent “Mixed round”, a back button on every screen. The right shape for the app's size.

Where it breaks

Maths shows 31 topics, many near-duplicates — me6 “Angles” next to angles, me11 next to ratio. Content bolted on in layers, never merged. Screen state is a string, so the hardware back button exits the app and nothing deep-links.

Direction

Fold the me1–me16 banks into their procedural topics as extra question styles; a child should see one “Angles”, not two. Sort topics by difficulty band. Add hash routing so back behaves.

Content & pedagogy

Strong but shallow
Now

Above-average teaching. Hints scaffold rather than reveal; every item has a worked explanation; distractors are real near-misses, so a guess isn't a free 25%. The “no visual reveals the answer” rule is enforced in code, across all four subjects.

Where it breaks

Depth is wildly uneven. Procedural maths holds hundreds of distinct prompts; vocabulary topics hold 6–8 items each and some grammar banks only 3–4. The anti-worksheet claim is only true for half the app.

Direction

Deepen the shallow pools — vocab first, target 30+ per topic — and move content to a validated data file with a QA pass, so scaling it isn't a code-and-rebuild slog. Add read-aloud for weaker readers on what is, after all, a literacy app.

Engagement & child wellbeing

Mixed
Now

Much of this is genuinely child-respectful: effort praise not ability praise, streak rewards capped, a garden that grows on a real daily clock, no ads, no purchases, no social comparison, fully offline. Two extra modes — Turbo and a platformer — add variety.

Where it breaks

The defaults lean on pressure. A 45-second timer is on for every question — that drives maths anxiety in the kids who struggle most. Hints cost coins, so the child with fewest right answers can least afford help. The streak shows “best vs current”, a small guilt loop, and resets hard on one missed day.

Direction

Default the timer off. Make the first hint free. Add a streak grace/freeze day and drop the best-vs-current cue. Keep Turbo — but as one mode among several, so the whole app doesn't equate fast with good.

Accessibility

Mixed
Now

Real foundations: a 44px tap-target token, ARIA roles on toggles and progress bars, global reduced-motion, mastery shown by icon and colour, and a dyslexia mode with evidence-based spacing.

Where it breaks

Quiz feedback isn't announced (no aria-live), so a screen-reader user never hears if they were right. SVG diagrams are injected raw with no text alternative — every diagram question is invisible. The dyslexia font is Comic Sans MS, absent on most school devices, so it silently falls back.

Direction

Add aria-live to the feedback block and a short text description to each visual. Bundle a real dyslexia face (OpenDyslexic or Lexend). Nudge muted-text contrast up, and add an in-app text-size control.

Architecture & scale

Strong, with blockers
Now

A clean three-layer split — UI over a pure, React-free engine over pure curriculum, dependencies pointing only downward — so the whole engine is Node-testable, and it is: 140 tests, including property-style checks across every topic and seed.

Where it breaks

One 325-line App god-component holds all routing and state as an if (screen === …) ladder — the one place the code violates its own open/closed ethic. Saves are localStorage-only (device-bound, silently lost in private mode). Content is hand-authored JS behind a rebuild.

Direction

Decompose App and add routing. Give content a validated data format with an authoring/QA step. Add optional cloud sync — or at least auto-export — for multi-device use. Bring the already-installed Playwright to bear on the quiz, timer and persistence paths.

E

Where to spend the effort

Ordered by impact-per-effort, in three phases. Phase one is almost entirely flipped defaults and small fixes — a day's work that changes how the app feels. Phase two is the real product work. Phase three is what unblocks real users at scale.

days, not weeks

F

Principles to hold the line on

The redesign should be measured against these. Several are already true in the code — the point is to make them non-negotiable as the app grows.

01

Effort, not speed

Praise the work, not the wits — and never make a clock the default. Fast is one mode, not the goal.

02

Help is free

A struggling child needs the hint most and can afford it least. Scaffolding is never behind the reward currency.

03

Never spoil the answer

A picture is a scaffold, not a giveaway. Enforce it in code, across every subject — as the app now does.

04

Progression you can feel

Getting better should visibly change the work, not just a coin count. Difficulty tracks the child.

05

Works on any device

School tablet, home phone, a parent's laptop. Progress follows the child, not the browser.

06

Kind by default

No dark patterns, no guilt loops, no pressure the child didn't choose. The defaults carry the ethics.
